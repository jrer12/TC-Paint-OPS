"Runs out at" walks the Build Plan's included, matched, paint-type rows in schedule order (month, then priority where given) and subtracts each row's paint demand from current stock — the row where a color first goes negative is shown as where you'd run out, assuming the plan is worked in that order.

Stock levels and reorder points here are shared and saved automatically. Re-importing an inventory file (Data & Import tab) refreshes current stock but keeps your reorder points.

How import works: upload the same style of workbook you originally gave me (BOM Cards / TC Production Schedule / Cerakote Inventory). It's parsed right here in the browser — nothing gets sent anywhere — and replaces the shared dataset for everyone who opens this tool.

BOM Cards: re-parses every SKU's process description for paint color codes and part associations. Schedule: re-matches MOD SKUs to BOM cards automatically (exact or close spelling); anything that doesn't match closely enough needs a manual pick in the Build Plan tab, same as before. Existing checkbox/quantity edits for MOD SKUs that still exist are kept. Inventory: pulls the most recent dated column as current stock and updates it, without touching the reorder points you've already set.

Importing here replaces the shared copy for everyone — there's no undo, so double-check the file before uploading if others are relying on the current numbers.
